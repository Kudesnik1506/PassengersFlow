# Боевые записи

Сюда кладутся видео с реальных остановок — те, по которым доводится проект и
оценивается результат. Отладочный набор с Викисклада лежит отдельно, в
[`../test_videos/`](../test_videos/SOURCES.md), и служит другой цели: ловить
грубые поломки логики и регрессии.

Разделение сделано потому, что смешивать их в одну метрику бессмысленно.
В отладочном наборе на шесть размеченных роликов приходится 15 событий, часть
снята не в целевых условиях (метро 640×480, съёмка с рук). Утверждать по нему
что-либо о точности нельзя — можно только замечать, что стало хуже.

## Чего мы ждём от боевой записи

Условия из «Области применимости» ([`../test_videos/SOURCES.md`](../test_videos/SOURCES.md)):

- **камера на штативе**, не в руках: при панорамировании не работает ни одна
  система координат — привязка к рамке ТС едет вместе с обрезкой, абсолютные
  пиксели едут вместе с автобусом;
- **транспорт целиком в кадре**, включая нижнюю кромку: счёт идёт по точке
  опоры человека, то есть по тому, где стоят ноги, а обрезанный низ её отнимает;
- **двери видны** — та сторона, через которую входят и выходят;
- **есть события**: пять минут в час пик дадут больше сигнала, чем весь
  нынешний набор.

Разрешение и частота кадров вторичны. Где узкое место — на сегодня не установлено:
в плотной группе на видео 04 конвейер удержал всех семерых, кто был виден, а
недостача оказалась за границей кадра ([021](../../docs/decisions/021-pyatero-na-04-za-kadrom.md)).
Единственный подтверждённый промах — одиночное событие при съёмке с рук (05).
Прежняя формулировка «узкое место в удержании личности» этим замером не
подтверждается; заново отвечать на этот вопрос надо по боевым записям.

## Порядок работы с новой записью

```bash
paxcount info data/prod_videos/<файл>          # параметры, наличие кэша
paxcount serve                                 # разметить двери мышкой
paxcount run data/prod_videos/<файл> --debug   # посчитать и посмотреть рендер
```

Затем событие за событием заполняется эталон (`data/truth/events.csv` и
`data/truth/truth.csv`), а ролику проставляется `domain = целевой`. С этого
момента он начинает влиять на метрику целевого домена — ту, по которой судят
результат.

Событие, которого с этой камеры физически не видно, помечается `observable: no`,
а не пропускается молча. Иначе получается эталон, недостижимый в принципе, — на
видео 04 такой ровно и получился.

## Счёт по кадрам

Заказчику нужны числа, а не система ([020](../../docs/decisions/020-zakazchik-pokupaet-chisla.md)),
и считать по кадрам может модель — на одиночных событиях она точнее конвейера.
Роль конвейера при этом сузилась до поиска транспорта и окон открытых дверей:
пропущенное окно счётчик уже не увидит, а лишнее лишь стоит токенов.

Отдельной команды для этого пока нет — она пишется под первую боевую запись,
когда станет видно, каковы там окна и плотность потока. Замеренный ориентир по
цене: около 12 тысяч токенов на секунду анализируемого видео при 5 кадрах в
секунду; полная частота не дала ничего сверх этого.

## Персональные данные

Кадры содержат лица и номера машин, поэтому папка целиком закрыта в
`.gitignore` — версионируется только этот файл. В репозиторий и в публичные
артефакты кадры не попадают; отладочное видео не публикуется без размытия лиц.
Стороннему счётному API кадры отдавать разрешено
([019](../../docs/decisions/019-kadry-uhodyat-v-schetnyy-api.md)) — это решение
заказчика, и конечного заказчика о нём надо уведомить до первой записи.
Подробнее — принцип 6 в [PRINCIPLES.md](../../PRINCIPLES.md).
