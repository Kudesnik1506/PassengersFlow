# Стенд сравнения методов локализации дверей

Отвечает на один вопрос: каким способом искать дверные проёмы на боевых
записях. Не на вопрос «работает ли конвейер» — это разные стенды.

```bash
uv run python tools/bench_doors.py --check     # кто готов, чего не хватает
uv run python tools/bench_doors.py             # прогон всех готовых
uv run python tools/bench_doors.py -m edges -m ensemble
uv run python tools/bench_doors.py --export out/bench_frames   # кадры глазами
```

## Вход

Только ручная разметка эталона из `data/truth/doors` (экран `/markup`). Рамка
кузова берётся оттуда же, а не из детектора: кэша детекции по боевым записям
нет, а сравнивать методы на разных рамках бессмысленно — разница рамок выдала бы
себя за разницу методов (решение 043).

Без разметки стенд запускать нечего: он честно скажет, что случаев ноль.

## Мера

Проём засчитан, если настоящий проём целиком попадает в кроп, нарезанный по
предсказанию (запас `CROP_MARGIN_PX` из `settings.py`). Не IoU — см. решение 043.
Рядом печатаются смещение центра и перекрытие по горизонтали, но зачёт решают
не они. Два прямоугольника на одну дверь — одно попадание и один лишний.

## Три исхода на метод

`ок` — отработал; `не установлен` — чего-то нет, и таблица говорит, чего
именно; `ошибка` — упал, и текст падения в таблице. Свести последние два к нулю
найденных дверей нельзя: ноль значит «посмотрел и не нашёл».

## Что требует установки руками

Дополнительные зависимости — отдельной группой, боевому конвейеру они не нужны:

```bash
uv sync --group bench                 # transformers (OWLv2, GroundingDINO)
uv pip install --no-build-isolation \
    "git+https://github.com/facebookresearch/detectron2.git"
```

`--no-build-isolation` обязателен: `setup.py` detectron2 импортирует torch на
этапе сборки, а изолированное окружение сборки его не содержит. Проверено на
Apple M5, torch 2.14: собирается, C++-расширение работает.

VLPart пакетом не ставится — репозиторий и веса кладутся руками:

```bash
git clone --depth 1 https://github.com/facebookresearch/VLPart models/VLPart
curl -L -o models/vlpart_r50_lvis_paco_pascalpart_partimagenet.pth \
  https://github.com/PeizeSun/VLPart/releases/download/v0.1/r50_lvis_paco_pascalpart_partimagenet.pth
```

Оба пути закрыты в `.gitignore`.

## Метод, отвечающий не кодом

`vlm` — указание дверей мультимодальной моделью. У проекта нет ключа к API
(владелец работает по подписке), поэтому кадры показываются модели в сессии, а
координаты кладутся файлом `data/bench/vlm/<ключ визита>.json`:

```json
{"boxes": [[x0, y0, x1, y1]], "note": "чем и как отвечала модель"}
```

Координаты — пиксели кадра, как у всех прочих методов. Строка таблицы прямо
говорит, что ответ получен вручную: сравнивать его по времени работы с
автоматическими методами нельзя, по попаданиям — можно.

## Отложено владельцем

`people` (двери по следам людей) — метод живёт на статистике сотен визитов, на
пяти машинах сгущения не образуются. Ждёт прогона по всей папке «Утро».

`finetune` (дообучение) — обучать не на чем, пока размечено пять визитов; нужно
150–300 кадров разнообразия, то есть 30–50 визитов.

Оба закрываются одной работой — разметкой утренней смены.

## Счёт людей по дверям каждого варианта

```bash
uv run python tools/bench_count.py            # пять вариантов дверей, один счётчик
uv run python tools/bench_count.py --refresh  # пересчитать детекцию, не брать кэш
```

Отвечает на вопрос в тех единицах, в которых сдаётся работа: не «промах 40 px»,
а «вошло столько-то». Варианты — ручная разметка (потолок, решение 050), три
модели по отдельности и их совет.

Три места, где превращение ответа метода в счёт может соврать, и как они
устроены (`src/paxcount/bench/counting.py`):

* **отбор.** У модели кандидатов бывают сотни; сколько из них дверей, знает
  таблица 3 по размеру ТС. Отбирает тот же арбитр, что в бою
  (`doorprop.layout.layout_from_candidates`), по убыванию уверенности самой
  модели — ради этого методы теперь возвращают уверенности (`finders.ranked`).
* **зона.** Считается полоса ног, а не проём (запрет 4): по горизонтали
  границы берутся у проёма, по вертикали — у кузова, доли берутся из умолчания
  `DoorSpec.zone`, где они измерены.
* **окно.** Дверная зона без машины — кусок тротуара. Окно стоянки находится
  по совпадению рамки ТС с размеченным кузовом (порог — `SAME_VISIT_IOU`,
  решение 047), а не назначается вокруг размеченного кадра.

Совет здесь собран иначе, чем метод `ensemble` в стенде: голосуют **ответы**
методов (по K дверей от каждого), а не сырые облака. Иначе участник, выдающий
девятьсот рамок на кадр, голосует за каждое место сразу, и вес «сколько методов
согласны» перестаёт что-либо значить.

Детекция людей идёт только по окнам стоянок (`bench/tracks.py`): кадры вне окон
пролистываются без раскодирования, кэш — на окно, трекер между окнами
сбрасывается. Проход по двадцатиминутному ролику ради шести стоянок стоит
секунды, а не часы (решение 022).
